| [WS·WSS 전송](websocket.md) | Draft | 내장 TLS(1.2 이상), 수락 직후·업그레이드 직전 IP 검사, 평문 WS 기본 비활성, Origin, 프레임·오류·종료, noVNC 외부 검증 | FR-05, 보안 |

## 적용 범위와 추적

- [PRD 확정 기준](../requirements/PRD.md#확정-기준)의 사용자 결정을 적용한다. 2026-10-16 검토에서 확정한 결정도 같은 표에 있다. 문서 전체의 Draft 상태와 개별 확정 사항을 구분하며, 지원 목표를 검증 완료로 표시하지 않는다.
- 각 문서의 규칙 ID는 독립적인 동작을, 시나리오 ID는 그 동작의 수용 조건을 가리킨다. PRD FR ID와 AC ID는 유지한다.
- [PRD의 추적 표](../requirements/PRD.md#14-관련-스펙과-추적)가 기능·보안·비기능 기준을 스펙과 시나리오에 연결한다.
- 업무 용어는 루트 [용어집](../../GLOSSARY.md)을 따른다.
- 수용 테스트 표는 시나리오와 기대 결과만 정의한다. 시나리오와 테스트의 연결은 테스트 소스 코드의 메타 정보로, 커버리지·결과는 메타 정보에서 생성한 보고서로 관리한다([검증 기록](../AGENTS.md#검증-기록)). 메타 정보 문법과 보고 명령은 [테스트 컨벤션](../conventions/testing.md)이 정한다. 보고서는 `cargo xtask scenarios`가 Cargo 대상 디렉터리의 `scenario-report.md`로 만든다. 시나리오별 연결과 결과는 이 보고서에서 확인하며 이 문서에는 적지 않는다. 테스트와 연결되지 않은 시나리오는 보고서에 `미연결`로 나온다. 문서 검증을 통신·UI·호환성 테스트 통과로 간주하지 않는다.
- 교환 계약 6건 중 설정·CLI·관리 API·WebSocket·운영 정보 5건은 2026-10-16에 사용자가 채택해 [계약 목록](../contracts/README.md)에 Active로 등록했다. Repeater 초기 교환 계약은 관찰 증거로 형식을 확정해 2026-11-01에 채택했다(사용자 결정 2026-11-01(Q73)). 같은 날 중복 ID 정책(RLY-TBD-003)도 후발 거절로 정했다(Q74·Q75). 설정 계약은 같은 날 2.0.0으로 올렸다(Q71). Active 계약의 계약 테스트는 일부만 있으며, 각 계약 5절이 테스트 위치와 결과를 적는다. 지원 완료로 표시하지 않는다. 기본값과 유효 범위의 수치와 TCP 진입점 기본 포트는 사용자가 승인했고 [설정 계약](../contracts/config-v2.md)이 기준이다. 허용 암호 스위트는 선택한 rustls 암호 모듈의 rustls 기본 목록으로 확정했다. Rust 라이브러리는 [PRD](../requirements/PRD.md#확정-기준) "구현 기술" 행이 기준이며 2026-10-20 의존성 라이선스 검토 뒤 확정했다. 대시보드 시각 기준은 [디자인 기준](../design/DESIGN.md)(2026-10-20 채택)이 정한다. rustls 암호 모듈(OPS-TBD-009)은 aws-lc-rs로 정해 해소했다. 고정 검증 버전은 [호환성 검증 기록](../contracts/repeater-compat-record.md)이 정한다(Ubuntu Repeater는 보류, 사용자 결정 2026-10-22(Q19)). 출처·MIT 고지 검토(OPS-TBD-005, OPS-021)와 측정 환경(OPS-TBD-004)은 각 스펙의 미결정 표에서 관리한다.

## 문서 검증 기록

- 확인일: 2026-10-17.
- 대상: 이번 작업트리의 스펙 5개, PRD 0.4, 계약 6개(Active 5·Draft 1), ADR 4개, 디자인 시스템 초안과 HTML 시안, 문서 목록·작업 지침·용어집. 템플릿 저장소 `../project-docs`의 커밋 `1c3cbce`까지 반영했다. 커밋 기준 검증이 아니다.
- 환경: Windows, Python 3.14.6, markdown-it-py 4.2.0.

| 확인 대상 | 방법 | 결과 | 관찰·제한 |
| --- | --- | --- | --- |
| 문서 구조·추적 | Python으로 표 열 수, ID 중복, 규칙별 수용 행, PRD의 시나리오 참조·범위, AC별 시나리오 연결, 문서가 인용한 시나리오·TBD ID의 존재(결번 문장 제외), 파일·제목 링크 검사 | 통과 | FR 8개·AC 35개 연결, 규칙 77개·수용 시나리오 146개 모두 PRD에서 추적, 템플릿을 뺀 문서 41개의 로컬 링크 1115개 정상. 스펙 4개의 수용 테스트 표는 4열, 화면 스펙은 5열(화면 ID 포함)이며 위치·결과·실행 기록 열이 없다 |
| 템플릿 반영 | Python으로 `../project-docs` 커밋 `1c3cbce`의 `docs/templates/`·`.agents/`·`docs/**/AGENTS.md`와 이 저장소 파일을 줄 끝(CR)을 빼고 바이트 비교 | 통과 | 차이 0건, 누락 0건. 루트 `AGENTS.md`와 `docs/README.md`는 프로젝트 내용을 유지하고 템플릿 변경만 병합했다 |
| Markdown 표시 구조 | markdown-it-py의 table 활성화 후 HTML로 메모리 렌더링, HTMLParser로 표·수용 행 확인 | 통과 | 스펙 5개에서 수용 행 146개 렌더링, 문서 구조 확인이며 실제 UI 시각 검증은 아님 |
| TCP·WS·WSS·실제 UltraVNC·브라우저 UI·로컬 CLI·자동 재로드·배포 | 시나리오 커버리지·결과 보고서(수용 테스트 표의 시나리오 ID와 테스트 메타 정보 대조) | 미실행 | 구현·테스트 코드·테스트 컨벤션(보고 명령) 없음. 실제 검증 버전·계정·인증서·IP 목록·한도·측정 환경 준비 필요 |

검증 스크립트와 렌더링 결과는 일회성 메모리 검사이며 저장소에 남기지 않았다. 실제 구현 검증 때는 테스트 소스에 시나리오 메타 정보를 기록하고, 커버리지·결과 보고서를 생성해 [검증 기록](../AGENTS.md#검증-기록)에 따라 연결한다. 이 문서에는 시나리오별 테스트 위치와 결과를 적지 않는다.

2026-10-22 추가 확인: 커밋 `439ce84`, Windows 11, `powershell -NoProfile -ExecutionPolicy Bypass -File D:/vr-tools/vr-win.ps1 -Only all`(내부에서 `cargo xtask scenarios` 실행). 보고서가 스펙 5개의 시나리오 150건을 읽었고 메타 정보 `오류`는 0건이다. 2026-10-17 기록의 146건에서 늘어난 시나리오에는 DASH-026·DASH-027(사용자 결정 2026-10-22(Q51))이 있다. 시나리오별 결과는 보고서에 있으며 이 문서에 옮기지 않는다.
