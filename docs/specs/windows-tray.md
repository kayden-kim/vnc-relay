# Windows 트레이 앱 스펙

Windows 11 사용자가 알림 영역(작업 표시줄 오른쪽의 아이콘 영역)에 있는 VNC Relay 아이콘과 메뉴로 Windows 서비스 `vnc-relay`를 다루는 동작을 정의한다. 사용자는 서비스 상태를 보고, 서비스를 시작·중지하고, 대시보드와 로그·설정 파일 위치를 연다. 트레이 앱은 별도 GUI 실행파일 `vnc-relay-tray.exe`다(사용자 결정 2026-11-17(Q240)). 서비스 자체의 시작·종료 동작은 [운영 스펙 3.7절](operations.md#37-windows-서비스-실행)이 정한다.

| 항목 | 값 |
| --- | --- |
| 상태 | Draft(2026-11-17). 범위·메뉴·동작은 사용자 결정 2026-11-17(Q240·Q250~Q256)을 따른다. 문구와 아이콘은 미결정이다(8절). 구현·시험은 미실행(구현 전)이다. |
| 관련 요구사항 | [PRD](../requirements/PRD.md) FR-10, AC-59 |
| 관련 아키텍처 문서 | 없음. 구현할 때 코드 지도와 모듈 설계를 작성한다. 계획 위치는 [코드 지도 8절](../architectures/code-map.md#8-계획과-문서-정리target)에 있다. |
| 관련 계약 | [CLI 계약 1.9절](../contracts/cli-v1.md#19-windows-서비스-실행)(서비스 이름·등록 명령), [설정 파일 계약](../contracts/config-v4.md)(읽는 키 4개), [운영 정보 계약 1.12절](../contracts/ops-info-v2.md#112-상태-리스너와-엔드포인트)(`/readyz`) |

## 1. 범위와 외부 주체

- 외부 주체: Windows 11 사용자(서비스 운영자, 관리자, 그 밖의 사용자), 서비스 제어 관리자(SCM, Windows가 서비스를 등록·시작·중지하는 구성 요소), 서비스 `vnc-relay`, 기본 브라우저, 파일 탐색기.
- 포함: 아이콘과 메뉴 표시, 서비스 상태 표시와 갱신, 시작·중지 요청, 대시보드 열기, 로그 파일·설정 파일 위치 열기, 로그인할 때 시작 설정, 트레이 끝내기, 메뉴 언어.
- 제외: 서비스 설치·해제는 [CLI 계약 1.9절](../contracts/cli-v1.md#19-windows-서비스-실행)이 정한다. 서비스의 시작·종료 동작은 [운영 스펙 3.7절](operations.md#37-windows-서비스-실행)이 정한다. 대시보드 기능은 [대시보드 화면 스펙](dashboard.md)이 정한다. 알림 풍선, 확인 대화상자, 다시 시작 메뉴(사용자 결정 2026-11-17(Q253)), Ubuntu, 한 PC의 여러 서비스(사용자 결정 2026-11-17(Q257))는 이 스펙에 없다.
- 플랫폼: Windows 11 x64만 대상이다. Windows Server는 검증하지 않는다.

## 2. 용어와 상태

업무 용어는 [VNC Relay 용어집](../../GLOSSARY.md)을 따른다. 아래 표는 트레이 앱이 표시하는 서비스 상태다. 트레이 앱은 SCM이 알려 주는 서비스 상태와 상태 리스너의 `/readyz` 결과로 표시 상태를 정한다.

| 이름 | 의미 | 진입 조건 | 종료 조건 |
| --- | --- | --- | --- |
| 서비스 없음 | 서비스 `vnc-relay`가 등록되지 않았다 | SCM 조회 결과 서비스가 없음(사용자 결정 2026-11-17(Q250)) | 서비스가 등록됨 |
| 중지됨 | 서비스가 멈춰 있다. 마지막 종료 코드가 0이 아니면 그 코드도 표시한다 | SCM 상태가 중지됨 | SCM 상태가 바뀜 |
| 시작 중 | 서비스가 시작 순서를 진행하고 있다 | SCM 상태가 시작 중 | SCM 상태가 실행 중 또는 중지됨 |
| 실행 중 | 서비스가 실행 중이고 준비됨이다 | SCM 상태가 실행 중이고 `/readyz`가 200 | SCM 상태 또는 `/readyz` 결과가 바뀜 |
| 실행 중(준비 안 됨) | 서비스는 실행 중이지만 준비됨을 확인하지 못했다 | SCM 상태가 실행 중이고 `/readyz`가 200이 아니거나, 연결에 실패하거나, 설정을 읽지 못함 | SCM 상태 또는 `/readyz` 결과가 바뀜 |
| 중지 중 | 서비스가 종료 절차를 진행하고 있다 | SCM 상태가 중지 중 | SCM 상태가 중지됨 |
| 확인 불가 | 서비스 상태를 알 수 없다 | 서비스 없음을 뺀 SCM 조회 실패, 또는 위 표에 없는 SCM 상태 | 다음 조회 성공 |

- 트레이 앱은 2초마다 상태를 다시 조회한다. 시작·중지 요청을 보낸 직후에도 다시 조회한다(이 문서의 판단, 사용자 결정 없음).
- `/readyz` 요청의 제한 시간은 1초다. 응답이 없으면 연결 실패로 본다(이 문서의 판단, 사용자 결정 없음).

## 3. 정상 흐름

1. 사용자가 `vnc-relay-tray.exe`를 실행한다. 로그인할 때 시작을 켰으면 Windows가 로그인할 때 실행한다.
2. 트레이 앱은 콘솔 창을 열지 않아야 한다. 관리자 권한을 요구해서도 안 된다(사용자 결정 2026-11-17(Q242)).
3. 같은 Windows 사용자의 트레이 앱이 이미 실행 중이면 새 프로세스는 아이콘을 만들지 않고 종료 코드 0으로 끝나야 한다(이 문서의 판단, 사용자 결정 없음).
4. 트레이 앱은 알림 영역에 아이콘 하나를 만든다. 아이콘에 마우스를 올리면 `VNC Relay: <상태>`를 보여 준다. 아이콘을 클릭하면 메뉴를 연다.
5. 트레이 앱은 SCM에서 서비스 `vnc-relay`의 상태와 등록 명령을 조회한다. 조회에는 상태 조회·구성 조회 권한만 요청한다. 서비스 핸들은 조회할 때마다 열고 닫는다. 그래서 서비스 해제를 막지 않는다(이 문서의 판단, 사용자 결정 없음).
6. 트레이 앱은 등록 명령의 `--config` 값으로 설정 파일 경로를 얻는다. 설정 파일을 [설정 파일 계약](../contracts/config-v4.md)에 맞게 읽고 `management.listen`·`management.cert_file`·`status.listen`·`log.output` 네 키만 쓴다. 상대 경로는 설정 파일의 디렉터리를 기준으로 푼다.
7. 서비스 상태가 실행 중이면 `status.listen`의 `/readyz`에 평문 HTTP `GET`을 보낸다. 주소가 `0.0.0.0`이면 `127.0.0.1`로, `::`이면 `::1`로 바꿔 보낸다(이 문서의 판단, 사용자 결정 없음).
8. 사용자가 메뉴 항목을 고르면 트레이 앱은 4절 표의 결과를 실행한다.
   - 시작: SCM에 시작을 요청한다. 시작·중지 권한은 이때만 요청한다.
   - 중지: 확인 없이 SCM에 중지를 요청한다(사용자 결정 2026-11-17(Q254)).
   - 대시보드 열기: 관리 리스너 주소로 대시보드 주소를 만들어 기본 브라우저로 연다(사용자 결정 2026-11-17(Q251)). `management.cert_file`이 있으면 `https`, 없으면 `http`다. 호스트가 `0.0.0.0`이면 `127.0.0.1`, `::`이면 `[::1]`로 바꾼다. IPv6 주소는 대괄호로 감싼다. 경로는 `/`다. 예: `management.listen = "0.0.0.0:8443"`이고 인증서가 있으면 `https://127.0.0.1:8443/`이다.
   - 로그 파일 위치 열기: 파일 탐색기에서 `log.output`의 로그 파일을 선택한 상태로 연다. 파일이 아직 없으면 그 디렉터리를 연다.
   - 설정 파일 위치 열기: 파일 탐색기에서 등록 명령의 설정 파일을 선택한 상태로 연다.
   - 로그인할 때 시작: 켜면 현재 사용자의 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`에 값 이름 `vnc-relay-tray`로 이 실행파일의 따옴표 친 절대 경로를 쓴다. 끄면 그 값을 지운다. 기본은 꺼짐이다(사용자 결정 2026-11-17(Q252·Q256)). 값 이름은 이 문서의 판단이다(사용자 결정 없음).
   - 트레이 끝내기: 아이콘을 지우고 트레이 앱을 끝낸다.
9. 메뉴 언어는 트레이 앱이 시작할 때 한 번 정한다. Windows 표시 언어가 한국어이면 한국어, 그 밖에는 영어다(사용자 결정 2026-11-17(Q255)). 표시 언어를 읽는 방법은 [ADR-0010](../decisions/ADR-0010-windows-service-and-tray.md) 6절의 미결정 사항이다.

## 4. 화면 구성과 와이어프레임

트레이 앱의 화면은 메뉴 하나다. 화면이 하나이고 입력 항목이 없으므로 별도 화면 스펙을 쓰지 않는다([스펙 작성 규칙](AGENTS.md)). 메뉴 모양은 Windows 기본 메뉴를 따른다. 아래 그림의 문구는 4.1절의 제안이다.

```text
(알림 영역의 VNC Relay 아이콘을 클릭)
+-------------------------------------+
| VNC Relay: 실행 중                  |  <- 상태 줄(누를 수 없음)
| 설정을 읽지 못함: 권한 없음         |  <- 설정 줄(설정을 읽지 못할 때만)
| 시작 실패: 권한 없음                |  <- 실패 줄(동작이 실패했을 때만)
+-------------------------------------+
| 시작                                |
| 중지                                |
+-------------------------------------+
| 대시보드 열기                       |
| 로그 파일 위치 열기                 |
| 설정 파일 위치 열기                 |
+-------------------------------------+
| [v] 로그인할 때 시작                |
+-------------------------------------+
| 트레이 끝내기                       |
+-------------------------------------+
```

| 구성요소 | 표시 내용·입력 | 사용자 행동 | 결과 | 관련 시나리오 |
| --- | --- | --- | --- | --- |
| 아이콘 | VNC Relay 아이콘 하나. 마우스를 올리면 `VNC Relay: <상태>` | 클릭 | 메뉴를 연다 | TRAY-001, TRAY-003 |
| 상태 줄 | `VNC Relay: <상태>`. 중지됨이고 마지막 종료 코드가 0이 아니면 `(종료 코드 N)`을 붙인다 | 없음. 누를 수 없다 | 없음 | TRAY-003, TRAY-007 |
| 설정 줄 | `설정을 읽지 못함: <원인>`. 설정을 읽지 못하는 동안만 보인다 | 없음. 누를 수 없다 | 원인이 없어지면 다음 갱신에서 사라진다 | TRAY-009 |
| 실패 줄 | `<동작> 실패: <원인>`. 원인은 권한 없음 또는 OS 오류 번호다 | 없음. 누를 수 없다 | 다음 메뉴 동작을 고르면 사라진다 | TRAY-006 |
| 시작 | 아래 켜짐 표를 따른다 | 누름 | SCM에 시작 요청 | TRAY-004 |
| 중지 | 아래 켜짐 표를 따른다 | 누름 | 확인 없이 SCM에 중지 요청 | TRAY-005 |
| 대시보드 열기 | 아래 켜짐 표를 따른다 | 누름 | 기본 브라우저로 대시보드 주소를 연다 | TRAY-008 |
| 로그 파일 위치 열기 | 설정을 읽었고 `log.output`이 파일 경로일 때 켜짐 | 누름 | 파일 탐색기에서 로그 파일을 선택한다. 파일이 없으면 디렉터리를 연다 | TRAY-010 |
| 설정 파일 위치 열기 | 등록 명령에서 설정 파일 경로를 얻었을 때 켜짐 | 누름 | 파일 탐색기에서 설정 파일을 선택한다 | TRAY-010 |
| 로그인할 때 시작 | 체크 항목. Run 값이 이 실행파일을 가리키면 체크된다. 항상 켜짐 | 누름 | 값을 쓰거나 지운다 | TRAY-011 |
| 트레이 끝내기 | 항상 켜짐 | 누름 | 아이콘을 지우고 끝낸다. 서비스와 Run 값은 그대로다 | TRAY-013 |

표시 상태별 켜짐은 다음과 같다. 시작·중지·대시보드 열기의 규칙은 이 문서의 판단이다. 서비스 없음의 규칙만 사용자 결정 2026-11-17(Q250)이다.

| 표시 상태 | 시작 | 중지 | 대시보드 열기 |
| --- | --- | --- | --- |
| 서비스 없음 | 꺼짐 | 꺼짐 | 꺼짐 |
| 중지됨 | 켜짐 | 꺼짐 | 꺼짐 |
| 시작 중 | 꺼짐 | 꺼짐 | 꺼짐 |
| 실행 중 | 꺼짐 | 켜짐 | 켜짐 |
| 실행 중(준비 안 됨) | 꺼짐 | 켜짐 | 꺼짐 |
| 중지 중 | 꺼짐 | 꺼짐 | 꺼짐 |
| 확인 불가 | 꺼짐 | 꺼짐 | 꺼짐 |

- 화면 상태: 설정을 읽지 못하면 설정 줄이 보이고 대시보드 열기·로그 파일 위치 열기가 꺼진다. 동작이 실패하면 실패 줄이 보인다.
- 디자인 원본: 없음.
- 공통 시각 기준: 아이콘은 미결정이다(TRAY-TBD-002). 메뉴는 Windows 기본 메뉴를 쓰며 색·글꼴을 따로 정하지 않는다.

## 5. 오류와 복구

| 조건 | 외부 결과 | 상태 변경 | 재시도 가능 여부 |
| --- | --- | --- | --- |
| 시작·중지 권한이 없음 | 실패 줄 `시작 실패: 권한 없음` 또는 `중지 실패: 권한 없음` | 서비스 상태는 그대로 | 조건부. 관리자가 서비스 운영자로 다시 설치한 뒤 가능 |
| 서비스가 없음 | 상태 줄 서비스 없음. 시작·중지·대시보드 열기·두 위치 열기가 꺼짐 | 없음 | 가능. 서비스를 설치하면 다음 갱신에서 반영 |
| SCM 조회 실패(서비스 없음 제외) | 상태 줄 확인 불가 | 없음 | 가능. 다음 갱신에서 다시 조회 |
| 등록 명령에 `--config`가 없음 | 설정 줄 `설정을 읽지 못함: 등록 명령에 설정 경로 없음`. 설정 파일 위치 열기도 꺼짐 | 없음 | 조건부. 서비스를 다시 설치한 뒤 가능 |
| 설정 파일을 읽지 못함(권한 없음·파일 없음·설정 오류) | 설정 줄. 대시보드 열기·로그 파일 위치 열기가 꺼짐. 서비스가 실행 중이면 실행 중(준비 안 됨) | 없음 | 가능. 원인을 없애면 다음 갱신에서 반영 |

| 시작 요청 뒤 서비스 시작 실패 | 시작 중을 거쳐 중지됨(종료 코드 N) | 서비스는 중지됨 | 조건부. 원인을 고친 뒤 가능([운영 스펙 5절](operations.md#5-오류와-복구)) |
| 브라우저·파일 탐색기 실행 실패, 디렉터리 없음 | 실패 줄 `OS 오류 {code}` | 없음 | 가능 |
| Run 값 쓰기·지우기 실패 | 실패 줄. 체크 표시는 실제 Run 값을 따른다 | Run 값은 그대로 | 가능 |

## 6. 항상 지켜야 할 규칙과 보장하지 않는 범위

- 트레이 앱은 서비스를 설치·해제하거나 서비스의 설정·접근 권한을 바꿔서는 안 된다.
- 트레이 앱은 관리 API를 호출하거나 관리자 로그인을 해서는 안 된다(이 문서의 판단, 사용자 결정 없음).
- 트레이 앱은 계정 파일·개인키·접속 ticket 공개 키 파일을 열어서는 안 된다(이 문서의 판단, 사용자 결정 없음).
- 트레이 앱을 끝내도 서비스 상태와 Run 값을 바꿔서는 안 된다.
- 이 스펙은 서비스가 시작된 뒤 고친 설정 파일과 실행 중 서비스의 주소가 같다고 보장하지 않는다. 트레이 앱은 지금의 설정 파일을 읽는다. 그래서 대시보드·`/readyz` 주소가 실행 중 서비스와 다를 수 있다.
- 이 스펙은 관리 리스너 인증서의 이름이 `127.0.0.1`·`[::1]`과 맞는다고 보장하지 않는다. 맞지 않으면 브라우저가 경고한다(사용자 결정 2026-11-17(Q251)).
- 상태 표시는 갱신 주기만큼(최대 2초) 늦을 수 있다.
- Windows Server와 Windows 11이 아닌 OS는 대상이 아니다.
