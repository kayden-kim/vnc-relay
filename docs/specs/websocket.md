# WS·WSS 전송 스펙

외부 Viewer가 WS 또는 서버 내장 TLS의 WSS로 중계 스트림에 접속하는 동작을 정의한다. 중계 접근은 관리자 로그인과 분리한 출발지 IP 허용 정책을 따른다.

| 항목 | 값 |
| --- | --- |
| 상태 | Draft |
| 관련 요구사항 | [PRD](../requirements/PRD.md) FR-05, 7절 보안 경계, AC-05~08 |
| 용어 | [VNC Relay 용어집](../../GLOSSARY.md) |
| 관련 스펙 | [중계와 매칭](relay.md), [설정·운영](operations.md) |
| 관련 계약 | [WebSocket 중계 v1](../contracts/websocket-relay-v1.md), [설정 파일 v1](../contracts/config-v1.md). 모두 Active(2026-10-16 채택)이며 URL·서브프로토콜·HTTP 상태·종료 코드의 이름·번호와 Origin 정규화는 이 계약이 기준이다. |
| 관련 아키텍처 문서·ADR | [ADR-0001 내장 TLS](../decisions/ADR-0001-built-in-tls.md), [ADR-0002 출발지 IP 허용 목록](../decisions/ADR-0002-source-ip-allowlist.md), [ADR-0004 tokio·rustls](../decisions/ADR-0004-tokio-rustls.md). 아키텍처 문서는 없고 구현 구조는 미확정이다. |

## 1. 범위와 적용 상태

- WS(`ws://`)·WSS(`wss://`) 지원은 사용자 확정 사항이다. 그 밖의 세부 동작은 Draft 제안이다.
- WS·WSS 진입점은 Viewer만 제공한다. Server는 TCP 역접속만 사용한다. 이 스펙은 WS·WSS Server 역접속을 정의하지 않는다. 이 결정은 사용자 확정 사항이다.
- Mode I·II 모두 확정 범위다. WS·WSS 각각에서 두 모드와 Mode II 양 접속 순서를 검증한다.
- 평문 WS 리스너는 기본 비활성이다. 설정에서 명시적으로 켠 경우에만 연다(WS-R12, WS-024). 테스트에서는 WS 리스너를 켜고 검증한다.
- noVNC, websockify 실행 파일, 원격 화면 렌더러를 의존성으로 추가하지 않는다. noVNC는 번들·배포물에도 넣지 않고 외부 상호운용 검증 대상으로만 쓴다.
- 검증 대상은 검증 시작 시 고정한 noVNC 버전의 [`repeaterID` 옵션](https://novnc.com/noVNC/docs/API.html)으로 접속하는 WS·WSS Mode II다(WS-025). Mode I은 대상이 아니다. 수용 판정은 매칭 성립과 noVNC의 RFB 연결 완료 관찰이다. noVNC 화면 렌더링은 수용 기준이 아니다.
- URL로 대상 주소나 중계 ID를 직접 지정하는 별도 중계 API를 만들지 않는다.

## 2. 상태와 리스너 책임

| 상태 | 진입 조건 | 종료 조건 |
| --- | --- | --- |
| 접속 수락 시 출발지 IP 검사 | WS·WSS 리스너가 TCP 접속을 수락한 직후, 데이터 읽기·TLS 협상 전 | 허용 목록에 있으면 WSS는 TLS 협상, WS는 업그레이드 대기로 진행. 없으면 TLS·HTTP 처리 전에 연결 종료 |
| TLS 협상 | 출발지 IP 검사를 통과한 WSS 연결이 VNC Relay의 내장 TLS 리스너에 접속 | TLS 성립 또는 협상 실패(TLS 1.2 미만 포함) |
| 업그레이드 대기 | HTTP WebSocket 요청 수신 | 업그레이드 직전 출발지 IP 재검사, 경로·Origin 검증 뒤 업그레이드 또는 거절 |
| Repeater 초기 교환 | WebSocket 연결 성립 | 호환 요청 완료, 오류, 시간 초과, 단절 |
| 대기·중계 | 유효한 Mode I·II 요청 | 중계 스펙의 정상 전이 또는 종료 사건 |
| 종료 중 | close, TCP 오류·EOF, 관리자 종료 | 종료 교환 완료 또는 정리 제한 만료 |
| 종료됨 | WebSocket·중계 자원 회수 | 같은 연결을 재사용하지 않음 |

TLS 협상과 HTTP 업그레이드 단계의 연결은 중계 연결 상한 L에 포함하고, 제한 시간 U를 적용한다([운영 스펙](operations.md#2-상태와-검증-매개변수)). 관리 API 요청은 중계 스트림으로 취급하지 않으며 관리 리스너 연결 상한 Lm으로 따로 센다.

VNC Relay가 WSS 리스너·인증서를 직접 관리한다. TLS 보호 구간은 클라이언트부터 VNC Relay까지다. 역방향 프록시 TLS 종료나 전달된 클라이언트 IP를 전제로 하지 않는다. 평문 WS 리스너는 기본 비활성이다. 켜면 시작 시 경고를 기록한다. 보호된 네트워크인지 판단하는 책임은 운영자에게 있다.

실제 연결 상대 IP를 해당 진입점의 출발지 IP 허용 목록과 대조하며 기본 허용은 금지한다. WS Viewer와 WSS Viewer는 각각 목록을 가진다. 켠 진입점의 목록이 없으면 시작에 실패한다([운영 스펙](operations.md#4-보안과-신뢰-경계)). 명시적으로 빈 목록이면 그 진입점의 모든 출발지를 거절한다. 목록 항목은 단일 IP, CIDR, 범위(`a-b`)를 받으며 IPv4·IPv6 모두 해당한다. 0.0.0.0/0·::/0 같은 전체 허용 항목을 명시적으로 쓰면 허용하고, 시작·재로드 때 경고를 기록한다. 잘못된 표기는 설정 오류다. 관리자 로그인 쿠키와 중계 ID는 IP 제한을 우회할 수 없다. IP 허용 정책은 같은 공인 IP를 공유하는 개별 사용자를 식별하지 않는다.

IP 목록과 인증서 재로드는 [운영 스펙](operations.md#33-파일-변경-자동-감지와-부분-재로드)에 따른다. 업그레이드 허용을 완료한 연결은 IP 제거 뒤에도 유지한다. 업그레이드 전의 HTTP·TLS 연결은 업그레이드 직전에 그 시점의 유효 목록으로 다시 검사한다. 재로드 뒤의 새 업그레이드에도 재로드 후 유효한 목록을 적용한다.

Origin 정책: Origin 헤더가 있으면 설정된 허용 값과 일치할 때만 업그레이드한다. 허용 값은 `scheme://host[:port]` 형식이며 정확 일치로 비교한다. 와일드카드는 없다. 스킴·호스트·포트 중 하나라도 다르면 거절한다. 하위 도메인은 다른 호스트다. 기본 포트 생략 표기를 같은 값으로 보는 것과 같은 정규화 세부는 [설정 계약 1.4절](../contracts/config-v1.md#14-origin-값-문법과-비교)이 정하고, 비교 결과에 따른 처리는 [WebSocket 계약 1.3절](../contracts/websocket-relay-v1.md#13-origin-비교)이 정한다. Origin 헤더가 없으면 출발지 IP 검사만 한다. 이때도 출발지 IP가 허용돼야 한다. Origin은 사용자 인증 수단이 아니다.

## 3. 정상 흐름과 규칙

1. WSS는 TLS가 성립한 뒤 HTTP 업그레이드를 진행한다. WS는 TLS 없이 업그레이드를 진행한다.
2. 관리 API와 구별되는 업그레이드 진입점에서 접속 수락 시와 업그레이드 직전에 실제 출발지 IP를 검사하고, 업그레이드 시 Origin 정책을 확인한다.
3. WebSocket 연결 뒤 바이너리 메시지의 페이로드를 연속된 Viewer 바이트 스트림으로 취급한다.
4. [중계 스펙](relay.md#3-정상-흐름)의 초기 교환으로 대상 주소 또는 ID를 얻는다. Repeater 계약 밖의 별도 선택 단계를 만들지 않는다.
5. 상대 TCP 스트림은 바이너리 메시지로 전달한다. 출력 메시지 크기나 경계가 입력과 같을 필요는 없다.

| 규칙 ID | PRD 근거 | 동작 |
| --- | --- | --- |
| WS-R01 | FR-05 | WS와 WSS 모두 바이너리 스트림 중계를 제공해야 한다. |
| WS-R02 | FR-05 | 여러 바이너리 메시지를 이어 붙인 바이트의 내용과 순서를 보존해야 한다. |
| WS-R03 | FR-05 | WebSocket 메시지 경계를 RFB 또는 Repeater 메시지 경계로 간주해서는 안 된다. |
| WS-R04 | FR-05 | 텍스트 데이터 메시지를 지원하지 않는 입력으로 거절해야 한다. |
| WS-R05 | FR-05 | ping·pong·close 제어 페이로드를 TCP 중계 스트림에 섞어서는 안 된다. |
| WS-R06 | FR-05 | 분할된 메시지에도 논리 메시지 전체 크기 제한을 적용해야 한다. |
| WS-R07 | FR-05 | 느린 TCP·WebSocket 수신자 양쪽에서 중계 버퍼 상한을 지켜야 한다. |
| WS-R08 | FR-05 | 관리 API 요청을 WebSocket 중계로 업그레이드해서는 안 된다. |
| WS-R09 | 7절 | WSS 협상 실패를 평문 WS 접속으로 자동 전환해서는 안 된다. |
| WS-R10 | 7절 | 출발지 IP는 TCP 접속 수락 직후(TLS·HTTP 처리 전)와 업그레이드 직전에 각각 당시 유효한 해당 진입점 목록으로 검사해야 한다. Origin 정책은 업그레이드 시 검사해야 한다. 어느 한 검사에 실패한 연결은 업그레이드·중계 등록 전에 거절해야 한다. |
| WS-R11 | FR-04·FR-05 | 연결 종료 후 WebSocket과 상대 TCP 연결의 자원을 정리해야 한다. |
| WS-R12 | 7절 | 평문 WS 리스너는 설정에서 명시적으로 켠 경우에만 열어야 한다. |
| WS-R13 | FR-05 | WS·WSS 연결에 Kw 주기로 ping을 보내고, Kw의 응답 제한 안에 pong이 없으면 끊긴 연결로 처리해 정리해야 한다. 서버 ping·pong은 WS-R05에 따라 TCP 중계 스트림에 섞어서는 안 된다. |

메시지 크기 제한 M은 프레임별 크기가 아니라 한 논리 메시지에 적용한다. 스트리밍 중 제한 초과를 확인할 때까지 일부 바이너리 데이터가 이미 전달될 수 있다. 초과 확인 뒤 추가 데이터 전달을 중지한다. 실패한 메시지 전체를 원자적으로 취소하는 보장은 하지 않는다.

끊긴 연결은 두 단계로 감지한다. WS·WSS의 하부 TCP 소켓에는 TCP keepalive(K)를 적용한다. WebSocket 계층에는 ping·pong(Kw)을 적용한다. 기본값과 유효 범위는 [설정 계약](../contracts/config-v1.md)이 정한다. pong에 응답하는 연결은 데이터가 없다는 이유만으로 끊지 않는다.

## 4. 오류와 종료

| 조건 | 클라이언트·상대가 관찰하는 결과 | 정리·재시도 |
| --- | --- | --- |
| TLS 협상·인증서 검증 실패 | WSS 연결 성립 실패 | 중계 등록 없음, 클라이언트가 설정을 고친 뒤 새 접속 |
| TLS 1.2 미만 협상 | WSS 협상 실패, 평문 전환 없음 | 중계 등록 없음, 규칙 [OPS-R17](operations.md#41-판정-가능한-규칙) |
| 잘못된 경로·업그레이드 요청 | HTTP 단계 거절 | 중계 ID 등록·대상 연결 없음 |
| 접속 수락 시 비허용 출발지 IP | TLS·HTTP 처리 전에 연결 종료 | 중계 등록·대상 연결 없음, 관리자 로그인으로 우회 불가 |
| 업그레이드 직전 출발지 IP 또는 Origin 정책 위반 | 업그레이드 전 접근 거절 | 신규 중계 세션 없음, 관리자 로그인으로 우회 불가 |
| 텍스트 메시지 | 지원하지 않는 데이터로 종료 | 텍스트를 TCP에 전달하지 않음 |
| 잘못된 프레임·논리 메시지 M 초과 | 프로토콜·크기 오류로 종료 | 원인 구분, 추가 전달 중지, 자원 회수 |
| Repeater 초기 교환 오류·시간 초과 | 호환 계약에 따른 종료 | 해당 대기·대상 연결 정리 |
| WebSocket close 수신 | 전체 WebSocket 종료 시작 | 상대 TCP에 EOF 의미 전달 후 제한 시간 안에 정리 |
| TCP 정상 EOF | WebSocket 종료 시작 | 이미 수락한 TCP 데이터 소진 후 close, 소진 불가 시 중단 원인 기록 |
| 네트워크 오류·종료 교환 시간 초과 | 비정상 종료 | 상대와 등록 자원 회수 |
| pong 응답 없음 | Kw의 응답 제한이 지난 뒤 비정상 종료. 서버 ping은 TCP 스트림에 전달하지 않음(WS-R05) | 끊긴 연결로 처리해 상대 TCP와 등록 자원 회수, 규칙 WS-R13 |
| 관리자 종료·프로세스 유예 만료·유예 중 두 번째 종료 요청 | 해당 세션의 양쪽 경로 종료. 두 번째 종료 요청은 남은 유예 없이 바로 종료([운영 스펙 3.4절](operations.md#34-정상-종료와-재시작)) | 완전한 잔여 데이터 전달은 보장하지 않음 |

WebSocket에는 TCP와 같은 독립적인 양방향 half-close가 없다. 따라서 WS·WSS가 포함된 연결은 한쪽 스트림 EOF 이후 반대 방향을 무기한 유지하지 않는다. 이 종료 의미와 오류별 HTTP 상태·close 코드의 대응은 [WebSocket 계약](../contracts/websocket-relay-v1.md)이 정한다(Active, 2026-10-16 채택). 코드 번호는 이 스펙이 아니라 그 계약이 기준이다.

서버가 자동으로 세션을 재접속·재매칭하지 않는다. 새 접속은 새로운 연결 수명이다.

## 5. 항상 지켜야 할 규칙과 비보장 범위

- TLS가 보호하는 구간과 TCP 평문 구간을 구분해 표시한다. WSS라는 이유로 전체 중계 경로가 종단 간 암호화된다고 표시하지 않는다.
- 다른 세션의 바이너리 데이터를 공유해서는 안 된다.
- 바이너리 페이로드 안의 RFB 인증·화면 데이터를 로그로 남겨서는 안 된다.
- 임의의 기존 WebSocket VNC 클라이언트가 호환된다고 보장하지 않는다. Repeater 초기 교환을 수행하는 클라이언트 계약이 필요하다. 다만 검증 시작 시 고정한 noVNC 버전의 `repeaterID`로 접속하는 WS·WSS Mode II는 검증 대상이다(WS-025). 이 검증은 그 버전과 테스트 환경에 한정한다.
- WS·WSS는 Viewer의 스트림 진입 방식이다. 원격 화면 표시 기능을 제공하지 않는다.

## 6. 전송·모드 검증 조합

아래 조합은 모두 검증 대상이다. noVNC 행은 외부 상호운용 검증이며 제품 의존성이 아니다. 일부 조합의 성공으로 전체 지원을 대체하지 않는다. TCP 전용 실제 화면·입력 테스트는 [중계 수용 테스트](relay.md#7-수용-테스트)이 소유한다.

| Viewer 진입 | 모드 | 상대·접속 순서 | 수용 시나리오 |
| --- | --- | --- | --- |
| WS | Mode I | 허용된 TCP 대상 | WS-001 |
| WSS | Mode I | 허용된 TCP 대상 | WS-002 |
| WS | Mode II | TCP Server 선접속 | WS-003 |
| WS | Mode II | WS Viewer 선접속 | WS-004 |
| WSS | Mode II | TCP Server 선접속 | WS-005 |
| WSS | Mode II | WSS Viewer 선접속 | WS-006 |
| WS | Mode II | noVNC `repeaterID`, TCP Server 선접속·후접속 | WS-025 |
| WSS | Mode II | noVNC `repeaterID`, TCP Server 선접속·후접속 | WS-025 |

## 7. 수용 테스트

WS-007 이후의 공통 중계 테스트는 WS·WSS 각각에 적용한다. TLS 전용 테스트는 서버 내장 WSS에 적용한다. WS 테스트는 평문 WS 리스너를 명시적으로 켠 설정에서 실행한다(WS-024). 테스트 코드는 `specs/`를 기준으로 한 이 문서의 상대 경로와 시나리오 ID를 메타 정보에 기록한다(예: `websocket.md:WS-001`). 연결 방식은 [검증 기록](../AGENTS.md#검증-기록)을 따른다. 테스트 위치와 결과는 이 문서에 적지 않는다.

| 시나리오 ID | 요구사항 ID | 조건과 입력 | 기대 결과 |
| --- | --- | --- | --- |
| WS-001 | FR-05 / WS-R01 | WS Mode I로 실제 TCP 대상에 접속 | 알려진 양방향 바이트 정확히 일치 |
| WS-002 | FR-05 / WS-R01 | WSS Mode I로 실제 TCP 대상에 접속 | 양방향 일치, VNC Relay까지 TLS 암호화 |
| WS-003 | FR-05 / WS-R01 | TCP Server 선접속 후 WS Mode II Viewer | 같은 ID 매칭 뒤 양방향 바이트 일치 |
| WS-004 | FR-05 / WS-R01 | WS Mode II Viewer 선접속 후 TCP Server | 반대 접속 순서에서도 양방향 일치 |
| WS-005 | FR-05 / WS-R01 | TCP Server 선접속 후 WSS Mode II Viewer | 양방향 일치, WSS 구간 TLS 성립 |
| WS-006 | FR-05 / WS-R01 | WSS Mode II Viewer 선접속 후 TCP Server | 반대 접속 순서에서도 양방향 일치 |
| WS-007 | FR-05 / WS-R02·WS-R03 | 같은 스트림의 메시지·프레임 경계를 바꿔 전송 | 상대가 받은 전체 바이트 내용·순서 동일 |
| WS-008 | FR-05 / WS-R04 | 텍스트 데이터 메시지 전송 | 미지원 데이터로 종료, 텍스트는 TCP에 도착하지 않음 |
| WS-009 | FR-05 / WS-R05 | 분할 바이너리 전송 중 ping·pong 삽입 | 제어 교환 처리, 스트림에 제어 바이트 없음 |
| WS-010 | FR-05 / WS-R06 | M 크기와 M+1 크기 메시지를 분할·비분할로 전송 | 경계 내 수락, 초과는 종료·추가 전달 중지 |
| WS-011 | FR-05 / WS-R07 | TCP 수신자·WS 수신자를 각각 지연 | 양 방향 버퍼 B 이내, 수신 재개 시 바이트 보존 |
| WS-012 | FR-05 / WS-R08 | 관리 API 경로 또는 잘못된 업그레이드 요청 | 중계 업그레이드·대기 등록·대상 연결 없음 |
| WS-013 | 7절 / WS-R09 | 만료·신뢰되지 않음·호스트 불일치 인증서에 검증 클라이언트 접속 | 각각 TLS 실패, 평문 자동 전환 없음 |
| WS-014 | 7절 / WS-R10 | 비허용 출발지에서 유효 관리자 쿠키·허용 IP 전달 헤더를 포함해 접속 | TLS·HTTP 처리 전 연결 종료, 쿠키·헤더로 IP 정책 우회 불가 |
| WS-015 | 7절 / WS-R10 | 허용 IP에서 비허용 Origin을 포함해 접속 | Origin 정책에 따라 업그레이드 거절 |

| WS-017 | FR-05 / WS-R11 | 전송 중 단절·close 응답 미도착 | 정리 제한 후 자원 회수, 다른 세션 영향 없음 |

| WS-019 | FR-05 / WS-R11 | 잘못된 프레임 순서 또는 유효하지 않은 제어 프레임 | 프로토콜 오류 종료, 등록 자원 회수 |

| WS-021 | 7절 / WS-R10 | 허용 IP의 비브라우저 클라이언트가 Origin·관리 세션 없이 접속 | IP 허용 및 호환 절차로 중계 가능, 관리자 로그인 요구 없음 |

| WS-023 | 7절 / WS-R10 | 비허용 출발지 IP가 WSS 리스너에 접속 | TLS 협상 전 연결 종료, 제한 시간 U 동안 L을 점유하지 않음 |

| WS-026 | FR-05 / WS-R13 | pong에 응답하지 않는 WS·WSS 클라이언트와 pong에 응답하는 유휴 클라이언트를 각각 둠 | 응답 없는 클라이언트: Kw 뒤 종료, 상대 TCP와 등록 자원 회수. 응답하는 유휴 클라이언트: 연결 유지. 서버 ping 바이트는 TCP 스트림에 섞이지 않음(WS-R05) |

## 8. 미결정 사항

확정 책임은 프로젝트 요구사항·운영 결정 담당자에게 있다. 외부 URL·HTTP 상태·종료 코드는 Active 계약이 기준이지만 구현·테스트가 없으므로 동작한다고 안내하지 않는다.

| ID | 항목 | 영향과 제약 | 확정 위치 |
| --- | --- | --- | --- |
| WS-TBD-004 | M·업그레이드/TLS 제한·종료 제한 | M·U·E의 기본값과 유효 범위는 사용자 승인으로 확정(설정 계약이 기준). 남은 것은 B와 M의 관계(M이 B보다 클 때의 메시지 처리)와 프레임 분할 우회·종료 중 자원 점유 검증(WS-010·WS-017) | [설정 파일 v1](../contracts/config-v1.md) 6절 |
| WS-TBD-005 | noVNC 검증 버전 고정·기록 방식 | 고정 버전과 기록이 없으면 WS-025 결과를 특정 버전의 증거로 볼 수 없다. 고정 버전 noVNC가 실제로 보내는 `Sec-WebSocket-Protocol` 값(기본 서브프로토콜)도 같은 관찰로 확인한다. 공개 문서 설명만으로 단정하지 않으며 결과가 계약과 다르면 계약을 고친다 | 호환성 검증 기록, 현재 미작성. [WebSocket 중계 v1](../contracts/websocket-relay-v1.md) 6절 |

WS-TBD-001은 결번이며 재사용하지 않는다. WS-TBD-002는 [WebSocket 중계 v1](../contracts/websocket-relay-v1.md) 채택(2026-10-16)으로 결정되어 4절과 계약에 반영했으며 재사용하지 않는다. WS-TBD-003은 [설정 파일 v1](../contracts/config-v1.md) 1.4절의 정규화 규칙 채택으로 결정되어 2절과 계약에 반영했으며 재사용하지 않는다. WS-TBD-006은 결정되어 1절에 반영했으며 재사용하지 않는다.
