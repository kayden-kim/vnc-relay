## 1. 결정

Viewer와 Server가 WS 리스너 하나, WSS 리스너 하나를 각각 공유한다. 정확한 `/relay` 경로는 Viewer, `/relay/server` 경로는 Server 역할을 선택한다(사용자 결정 2026-11-08(Q181·Q188)). Server는 TCP Server와 같은 Mode II 초기 교환을 사용한다.

설정은 리스너 표 `[relay.ws]`·`[relay.wss]`와 그 아래 역할 표 `viewer`·`server`로 나눈다. 리스너는 주소·신뢰 프록시·WSS 인증서를 갖고, 역할은 활성화 여부·IP 허용 목록·Origin 허용 목록을 갖는다. 이 구조는 `vnc-relay-config` 4.0.0의 호환성 파괴 변경이다.

운영 로그의 `listener`는 소켓인 리스너를 뜻한다. WS·WSS에서는 요청 경로를 읽기 전까지 역할을 모른다. 이 의미 변경은 `ops-info` 2.0.0으로 올린다. 정확한 필드와 이전 규칙은 [운영 정보 계약](../contracts/ops-info-v2.md)을 따른다.

## 2. 배경

사용자 지시 2026-11-08이 WS·WSS Server 지원을 요구했다. 사용자 결정 2026-11-08(Q181)이 기존 리스너를 공유하고 경로로 역할을 선택하는 구조를 골랐다. Q188은 합집합 수락 검사, 설정 이전, 운영 로그 major 변경과 설정 API·화면 키 변경을 수용했다. 사용자가 이 구조를 고른 다른 이유는 기록하지 않는다.

- 맥락 없이 보면 의외인 점: TCP는 리스너로 역할을 알지만 WS·WSS는 HTTP 경로를 읽기 전까지 역할을 알 수 없다.
- 되돌리기 어려운 이유: 배포 포트, 클라이언트 URL, 설정 표, 로그 소비자가 함께 바뀐다. 별도 리스너 구조로 다시 옮기려면 이 소비자를 모두 이전해야 한다.
- 진입점은 리스너와 역할의 조합이다. 용어는 [용어집](../../GLOSSARY.md)을 따른다.

## 3. 결정 요인

1. 사용자 결정의 공유 리스너·경로별 역할 구조를 충족하는가.
2. 배포 포트·인증서·프록시 경로 구성에 미치는 영향.
3. 수락 시 역할 판정과 역할별 접근 경계.
4. 설정과 운영 로그 소비자의 호환성 비용.

## 4. 선택 근거

공유 리스너는 사용자 결정 2026-11-08(Q181·Q188)을 그대로 적용한다. 한 포트와 한 인증서로 두 역할을 받을 수 있다. 역방향 프록시는 `/relay` 접두사를 하나의 upstream으로 보낼 수 있다. 이는 선택의 효과이며 사용자가 선택한 이유로 추정하지 않는다.

역할은 업그레이드 경로에서 정한다. 따라서 수락 때는 해당 리스너에서 켠 역할들의 허용 목록 합집합을 검사한다. 신뢰 프록시는 [ADR-0007](ADR-0007-proxy-tls-termination.md)의 별도 신뢰 경계를 따른다. 업그레이드 때는 선택한 역할의 허용 목록으로 클라이언트 주소를 다시 검사한다. 다른 역할 목록의 허용으로 이 검사를 통과할 수 없다.

## 6. 결과

### 긍정적 결과

- Viewer의 기존 `/relay` 경로를 유지하면서 `/relay/server`를 추가한다.
- 두 역할이 포트와 WSS 인증서를 공유한다.
- TCP·WS·WSS를 섞은 Mode II 연결에도 같은 초기 교환과 중복 ID 규칙을 사용한다.

### 부정적 결과와 비용

- 수락 때 역할을 모르므로 역할별 검사만으로 수락을 결정할 수 없다. 합집합 검사와 업그레이드 검사를 구분해야 한다.
- WS·WSS `connection_accepted`에서 역할을 생략한다. 기존 리스너 이름과 역할 필드를 전제로 한 로그 소비자는 ops-info 2.0.0에 맞춰 옮겨야 한다.
- 설정 v3 표를 v4 서버가 읽지 않는다. 운영 중인 `relay.toml`을 배포 전에 이전해야 한다. 이전과 롤백은 [설정 계약 3.3절](../contracts/config-v4.md#33-v3-파일을-v4로-옮기기)을 따른다.
- 설정 API와 대시보드의 키도 v4 이름으로 바뀐다. 재로드 대상은 33개, 편집 대상은 29개다.

### 후속 작업

- [ADR-0002 후속](ADR-0002-source-ip-allowlist.md#8-재검토-조건)과 관련 스펙·계약에서 리스너와 진입점을 구분한다.
- 구현은 커밋 `3df0693`이다. 시험은 커밋 `51bd747`의 두 OS 게이트에서 통과했다([WSS Server·프록시·최근 로그 판정표](../how-to/set-up-and-verify.md#43-wss-server프록시-tls-종료최근-로그-판정표)).

## 8. 재검토 조건

- 역할별 독립 포트·인증서 또는 서로 다른 배포 경계가 요구사항으로 채택된다.
- 공유 리스너의 합집합 검사와 업그레이드 역할 검사 사이에서 정책 우회가 기록된다.
- (해결) v4 키를 반영한 SCR-004·SCR-005 프레임 변경은 사용자 결정 2026-11-08(Q189)으로 채택했다. [화면 스펙](../specs/dashboard.md#8-미결정-사항)에서 관리한다.
