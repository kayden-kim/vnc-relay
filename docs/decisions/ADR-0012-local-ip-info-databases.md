## 1. 결정

접속 출처 통계의 국가와 ASN(인터넷 경로를 운영하는 조직의 번호)은 운영자가 내려받아 둔 MaxMind DB(MMDB) 형식 파일에서 찾는다. 서버는 IP 정보를 찾으려고 외부 서비스에 요청하지 않는다. DB 파일은 배포 묶음에 넣지 않고 서버가 내려받지도 않는다(사용자 결정 2026-11-20).

같은 읽기 코드가 DB-IP Lite, IPinfo Lite, MaxMind GeoLite·GeoIP2 파일을 모두 읽는다. 제공자를 설정으로 고르지 않는다. 파일 안의 필드 이름으로 국가·ASN 값을 찾고, 메타데이터의 `database_type`으로 제공자를 판정해 화면의 출처 표시를 고른다. 판정 규칙은 [설정 계약 1.12절](../contracts/config-v4.md#112-ip-정보-db-파일-형식)이 정한다(이 문서의 판단, 사용자 결정 2026-11-20의 "세 제공자 지원"을 구현하는 방식).

MMDB 읽기에는 `maxminddb` crate(ISC)를 쓴다. 파일 전체를 메모리로 읽고 전체 검사(`verify`)를 통과한 파일만 쓴다. 메모리 매핑(mmap)은 쓰지 않는다. 파일 크기는 256 MiB까지다(이 문서의 판단).

DB 파일 경로 `ip_info.country_db`·`ip_info.asn_db`는 재시작이 필요한 설정이다. 경로가 가리키는 파일의 내용은 파일 변경 감지로 다시 읽는다. 다시 읽기에 실패하면 이전 DB를 계속 쓰고 경고한다. DB가 없거나 읽지 못해도 서버는 시작하고 중계를 계속하며, 국가·ASN 값만 비운다(사용자 결정 2026-11-20의 "경고 후 계속", 재시작·감지 구분은 이 문서의 판단).

## 2. 배경

운영자는 접속이 어디서 오는지와 어느 주소가 자주 거절되는지 보려고 운영 로그의 주소를 따로 모아 외부 조회 사이트에 붙여 넣었다. 접속 출처 통계는 이 일을 대시보드에서 하게 한다([운영 스펙 3.9절](../specs/operations.md#39-접속-출처-통계)). 주소만으로는 국가와 네트워크 운영자를 알 수 없으므로 IP 정보 출처가 필요하다.

- 맥락 없이 보면 의외인 점: 서버가 국가·ASN 자료를 직접 받지 않고, 운영자가 파일을 내려받아 경로를 설정해야 한다. 화면의 ipinfo.io 링크는 있지만 서버는 ipinfo.io API를 부르지 않는다.
- 되돌리기 어려운 이유: 설정 키·파일 형식·제공자 판정·관리 API의 `databases` 필드·운영 로그 사건이 이 선택을 그대로 드러낸다. 외부 API 방식으로 바꾸면 설정·비밀 관리·네트워크 정책·개인정보 안내를 모두 다시 정해야 한다.
- 범위: 중계 동작, 출발지 IP 검사, `/metrics`, 운영 로그의 주소 필드는 바꾸지 않는다. [ADR-0003](ADR-0003-single-instance-memory-state.md)의 단일 인스턴스·메모리 상태를 유지한다.

## 3. 결정 요인

1. 외부 전송 없음. 클라이언트 IP를 서버가 제3자에게 보내지 않아야 한다. 인터넷이 막힌 망에서도 동작해야 한다.
2. 라이선스. 배포 묶음과 의존성이 [PRD 구현 기술 행](../requirements/PRD.md#확정-기준)과 [라이선스 검토](../how-to/check-dependency-licenses.md)를 통과해야 한다. 제3자 DB의 이용 조건이 저장소 배포에 섞이면 안 된다.
3. 중계 영향. DB 읽기·조회가 실패하거나 느려도 중계·시작이 멈추면 안 된다.
4. 운영 부담. 운영자가 고른 제공자의 파일을 그대로 쓰고, 파일을 바꾸면 재시작 없이 반영돼야 한다.
5. 손상 파일 대응. 복사가 덜 된 파일이나 다른 형식의 파일을 조용히 받아들이면 안 된다.
6. 메모리·속도. 국가·ASN 파일 두 개를 메모리에 두고 연결 사건마다 찾아도 부담이 작아야 한다.

## 4. 선택 근거

세 제공자는 모두 MMDB 형식으로 무료 파일을 배포한다. DB-IP Lite는 CC BY 4.0, IPinfo Lite는 CC BY-SA 4.0, GeoLite는 MaxMind GeoLite EULA를 따른다. 운영자가 직접 받으면 이용 조건은 운영자와 제공자 사이의 일이다. 저장소와 배포 묶음은 제3자 DB를 담지 않으므로 [라이선스 검토](../how-to/check-dependency-licenses.md)의 허용 목록을 바꾸지 않는다. 화면은 쓰는 DB의 제공자가 요구하는 출처 표시를 보인다([화면 스펙 SCR-008](../specs/dashboard.md#scr-008-접속-출처)).

필드 이름은 제공자마다 다르다. IPinfo Lite는 `country_code`·`asn`(`"AS13335"` 문자열)·`as_name`을 쓰고, DB-IP Lite와 MaxMind는 `country.iso_code`·`autonomous_system_number`·`autonomous_system_organization`을 쓴다. 파일의 처음 4096개 레코드에서 필드를 찾아 한 번 정하면 제공자 설정 없이 세 형식을 읽는다. 국가와 ASN이 한 파일에 든 IPinfo Lite는 두 키에 같은 경로를 넣고 한 번만 읽는다.

`maxminddb` 0.33은 ISC 라이선스이며 하위 의존성(`ipnetwork`, `memchr`, `serde`, `thiserror`)도 허용 목록 안이다. 기본 기능만 쓰면 mmap과 `unsafe` 매핑 코드가 빌드에 들어가지 않는다. 2026-11-20에 이 crate로 DB-IP Lite 2026-11 파일을 측정했다. 측정 PC는 Windows 11 개발 PC이고, release 빌드의 임시 시험 프로그램으로 한 번씩 실행했다. 국가 파일(8.5 MB)은 읽기 6 ms, 전체 검사 36 ms였다. 조회는 같은 주소 하나를 따로 데우지 않고 10만 번 되풀이해 찾은 시간이 17 ms였다. 서로 다른 주소를 찾는 실제 부하의 값이 아니다. ASN 파일(9.6 MB)의 전체 검사는 49 ms였다. 이 값은 이 파일과 PC에 한정된 관찰이며 보장 값이 아니다. 전체 검사는 시작·다시 읽기 때 한 번만 하므로 비용이 작고, 덜 복사된 파일을 쓰기 전에 거른다(요인 5·6).

파일 전체를 메모리로 읽으면 운영자가 파일을 덮어써도 쓰는 DB가 바뀌지 않는다. mmap은 Windows에서 파일을 잠가 교체를 막고, Linux에서는 덮어쓴 내용이 읽는 중에 보일 수 있다. 크기 상한 256 MiB는 지금 제공자의 국가·ASN·도시 파일보다 크고, 잘못된 경로로 큰 파일을 메모리에 올리는 일을 막는다.

경로를 재시작 설정으로 둔 것은 기존 재로드 규칙과 맞추기 위해서다. 경로가 바뀌면 감시 대상 목록이 바뀌는데, 지금 재로드 경로는 실행 중 감시 목록을 설정 파일·TLS·ticket 키 파일로 다룬다. 내용 변경은 TLS 인증서처럼 파일 변경 감지로 처리하되 설정 재로드의 후보로 만들지 않는다. 그래서 DB 파일 오류가 설정 재로드를 거절하거나 재시작 대기 상태에 막히지 않는다([설정 계약 1.8절](../contracts/config-v4.md#18-재로드-구분) 규칙 11).

## 6. 결과

### 긍정적 결과

- 운영자는 대시보드에서 주소·국가·ASN별 연결 시도·거절·중단·세션 수를 본다. 외부 망이 막힌 곳에서도 동작한다.
- 클라이언트 IP는 서버 밖으로 나가지 않는다. 관리자가 조회 링크를 고를 때만 그 IP나 ASN이 브라우저에서 ipinfo.io로 간다.
- DB 파일을 바꾸면 재시작 없이 반영되고, 잘못된 파일은 이전 DB를 지키면서 경고로 알린다.

### 부정적 결과와 비용

- 운영자가 DB를 내려받고 갱신해야 한다. GeoLite는 MaxMind 계정이 필요하고, 이용 조건에 따라 새 파일이 나오면 일정 기간 안에 바꿔야 한다. 절차는 [중계 서버 운영 how-to](../how-to/operate-relay.md)가 안내한다.
- DB 파일 크기만큼 메모리를 더 쓴다. 국가·ASN 두 파일이면 수십 MB다. IPinfo Lite처럼 한 파일이면 한 번만 읽는다.
- 국가·ASN 값의 정확도는 제공자 DB에 달려 있다. 서버는 값을 고치거나 검증하지 않는다.
- `maxminddb` crate 하나와 하위 crate `ipnetwork`가 의존성에 늘어난다.
- 경로를 바꾸려면 재시작해야 한다.

### 후속 작업

- PRD AC-63~65와 각 스펙 시나리오를 구현·테스트에 연결한다.
- 테스트는 내려받은 DB 대신 테스트 코드가 만든 작은 MMDB 파일을 쓴다. 저장소에 제3자 DB를 넣지 않는다.
- 도움말과 운영 how-to에 제공자별 내려받기·갱신·출처 표시를 싣는다.
- 대시보드 SCR-008은 디자인 기준과 시안을 사용자가 채택한 뒤 구현한다.

## 8. 재검토 조건

다음 재검토 조건은 이 ADR의 판단이다.

- 주로 쓰는 제공자가 MMDB 배포를 멈추거나 필드 이름을 바꾼다.
- DB 파일이 256 MiB를 넘는 제공자를 지원해야 한다.
- 운영자가 서버의 외부 API 조회를 명시적으로 요구한다.
- 다중 인스턴스를 도입하여 [ADR-0003](ADR-0003-single-instance-memory-state.md)의 상태 소유 기준이 바뀐다.
