## 1. 결정

출발지 IP 허용 목록 위에 WS·WSS 역할별 접속 ticket 확인을 더한다. 기본은 꺼짐이다. 설정으로 켠 역할은 ticket을 필수로 받는다. ticket이 있을 때만 확인하는 방식은 두지 않는다(사용자 결정 2026-11-11(Q192·Q193·Q196)).

접속 ticket은 외부 발급 쪽이 서명한다. VNC Relay는 역할마다 설정한 공개 키로 확인한다. 관리 세션을 발급하거나 재사용하는 기능이 아니다. 역할마다 발급자와 공개 키를 두고, 같은 역할의 WS·WSS 리스너에 함께 적용한다. 두 역할은 서로 다른 서명 키를 쓴다(사용자 결정 2026-11-11(Q197·Q207)). 용어는 [용어집](../../GLOSSARY.md#접근-경계)을 따른다.

확인 실패는 101 전에 HTTP 401로 거절한다(사용자 결정 2026-11-11(Q202)). 한 ticket은 한 번만 받아들인다. 재시작 뒤에는 기동 시각 + 5초 이하에 발급한 ticket도 거절한다(사용자 결정 2026-11-11(Q201)). ticket으로 연 연결은 그 ticket이 묶은 중계 ID만 쓴다. Viewer Mode I는 거절한다. 세션 만료 시각이 있으면 그 시각에 연결을 끝낸다. 형식과 확인 순서, 사용 기록, 종료 규칙은 [WebSocket 계약 1.9절](../contracts/websocket-relay-v2.md#19-접속-ticket)을 따른다(사용자 결정 2026-11-11(Q203·Q204·Q213)).

TCP 진입점은 ticket을 확인하지 못한다. 같은 역할의 TCP 진입점이 켜져 있으면 경고하되 시작·재로드를 거절하지 않는다. 평문 WS에서도 켤 수 있지만 그 구간은 믿을 수 있는 망 안에 있어야 한다. 이때도 경고한다(사용자 결정 2026-11-11(Q198·Q199)).

이번에는 기준 문서만 바꾼다. 구현·계약 테스트는 미실행(구현 전)이다(사용자 결정 2026-11-11(Q211)). 대시보드의 ticket 키 편집 입력과 `session_expired` 문구는 구현 작업에서 시안·문구(CPY)와 함께 정한다(사용자 결정 2026-11-11(Q214)).

## 2. 배경

[ADR-0002](ADR-0002-source-ip-allowlist.md)는 중계 ID를 인증 수단으로 보지 않는다. 출발지 IP 허용 목록은 모든 진입점의 기본 통제다. 다만 같은 허용 IP를 공유한 개별 사용자는 구분하지 못한다. ID를 추측하거나 얻은 쪽을 목록만으로 구분할 수 없다는 한계가 있다.

- 맥락 없이 보면 의외인 점: 모든 중계 연결에 인증을 강제하지 않는다. WS·WSS에서 설정으로 켠 역할만 추가로 확인한다. 관리자 로그인이 있어도 중계 권한과 결합하지 않는다.
- 되돌리기 어려운 이유: 발급 쪽·클라이언트·서버가 ticket 형식, 역할, 중계 ID와 사용 기록을 함께 따른다. 배포 뒤 이를 바꾸면 세 구성 요소와 로그 소비자를 함께 옮겨야 한다.
- 범위: [ADR-0008](ADR-0008-shared-ws-listener-path-roles.md)의 공유 리스너와 경로별 역할 위에 확인을 더한다. Repeater 초기 교환의 바이트 형식과 TCP 접근 통제는 바꾸지 않는다. 사용처의 기기 배포 방식은 이 ADR의 기준이 아니다.

## 3. 결정 요인

1. 기존 배포 영향. 명시적으로 켜기 전에는 기존 클라이언트 판정을 유지한다.
2. 비인가 연결 차단. 중계 ID 추측과 ticket 재사용을 막는다.
3. 차단 시점. ticket 확인 실패는 101 전에 거절한다.
4. 권한 분리. 관리 권한을 중계 접속 권한으로 쓰지 않는다.
5. 상태 모델. [ADR-0003](ADR-0003-single-instance-memory-state.md)의 단일 인스턴스·메모리 상태를 유지한다.
6. 운영 부담. 발급자·키 교체와 설정 재로드를 관리할 수 있어야 한다.
7. TCP 경로. ticket을 실을 수 없는 경로의 한계를 숨기지 않는다.

## 4. 선택 근거

기본 꺼짐은 사용자 결정 2026-11-11(Q192)의 선택이다. 기존 클라이언트는 ticket을 보내지 않으므로 항상 켜면 현재 배포의 접속 조건이 바뀐다. 역할마다 켜는 방식은 발급 쪽과 클라이언트를 준비한 뒤 적용할 수 있다. 호환 변경으로 내기 위해 `websocket-relay` 2.1.0과 계약 3절의 호환 변경 목록을 함께 고친다(사용자 결정 2026-11-11(Q195)). 전환과 롤백은 [WebSocket 계약 3.2절](../contracts/websocket-relay-v2.md#32-ticket-확인을-켜고-끄기)을 따른다.

101 전 HTTP 401은 사용자 결정 2026-11-11(Q202)을 적용한다. 실패한 요청은 WebSocket 연결로 받아들이지 않는다. 대기 등록·대상 연결 전에 거절하므로 접속 허가와 중계 절차를 나눈다. 101 뒤에야 읽을 수 있는 초기 요청의 중계 ID는 별도로 대조한다. 이 구분은 기존 Repeater 초기 교환을 바꾸지 않으면서 ID를 ticket에 묶는다.

서명만 확인하면 유효 기간 안에 같은 ticket을 다시 보낼 수 있다. 사용 기록을 메모리에 두어 두 번째 사용을 거절한다. [ADR-0003](ADR-0003-single-instance-memory-state.md)의 상태 모델에 맞추므로 외부 저장소는 추가하지 않는다. 재시작하면 기록이 사라지는 한계는 `iat > 기동 시각 + 5` 조건으로 메운다(사용자 결정 2026-11-11(Q201)). 기록 시점·보관 기간과 101 전송 실패 때의 소비 규칙은 [WebSocket 계약 1.9.4절](../contracts/websocket-relay-v2.md#194-사용-기록)이 정한다.

외부 발급 쪽과 역할별 공개 키는 관리 로그인을 중계 권한으로 쓰지 않게 한다. 역할마다 다른 서명 키를 쓰므로 두 역할의 키도 섞지 않는다(사용자 결정 2026-11-11(Q197·Q207)). 켜고 끄는 키는 재로드·관리 API 편집 대상으로 두며 기존 연결은 이전 값을 유지한다(사용자 결정 2026-11-11(Q200)).

## 6. 결과

### 긍정적 결과

- 출발지 IP 허용 목록을 유지하면서 켠 역할의 접속을 한 중계 ID의 일회용 허가에 묶는다.
- ticket 확인 실패는 대기 등록·대상 연결 전에 HTTP로 거절한다.
- 외부 발급 쪽이 중계 허가를 맡고 VNC Relay의 관리자 로그인과 분리한다.
- 기본 꺼짐과 재로드로 역할별 도입·해제를 나눌 수 있다.

### 부정적 결과와 비용

- TCP는 ticket으로 보호하지 못한다. 같은 역할의 TCP 진입점이 열려 있으면 `ticket_tcp_bypass`로 경고하지만 막지 않는다(사용자 결정 2026-11-11(Q198)).
- 평문 WS에서는 ticket이 노출된다. 믿을 수 있는 망 안에서만 써야 하며 `ticket_plaintext_ws` 경고를 남긴다(사용자 결정 2026-11-11(Q199)).
- 재시작 뒤 기동 시각 + 5초 이하에 발급한 ticket은 아직 `exp` 전이어도 거절한다. 클라이언트는 새 ticket을 받아야 한다(사용자 결정 2026-11-11(Q201)).
- 발급 쪽과 VNC Relay의 시계를 5초 안으로 맞춰야 한다. 발급 쪽은 역할별 서명 키와 중복되지 않는 `jti`를 관리한다. 의무는 [WebSocket 계약 1.9.7절](../contracts/websocket-relay-v2.md#197-발급-쪽과-클라이언트의-의무)을 따른다.
- 역할별 `max_lifetime_secs` 상한과 키 교체를 관리해야 한다(사용자 결정 2026-11-11(Q207·Q212)). 재로드 대상은 43개, 편집 대상은 37개로 늘어난다. 공개 키 파일 경로는 편집하지 않는다.
- 대시보드의 ticket 키 편집 입력과 `session_expired` 문구는 아직 미결정이다. 기존 시안·문구 채택을 새 범위의 채택으로 보지 않는다(사용자 결정 2026-11-11(Q214)).

### 후속 작업

- [PRD AC-49~52](../requirements/PRD.md#10-검증-및-수용-기준)와 각 스펙 시나리오를 구현·테스트에 연결한다. 구현·계약 테스트는 미실행(구현 전)이다(사용자 결정 2026-11-11(Q211)).
- [화면 스펙 DASH-TBD-006](../specs/dashboard.md#8-미결정-사항)에 따라 구현 작업에서 시안·문구(CPY)를 정한다(사용자 결정 2026-11-11(Q214)).

## 8. 재검토 조건

다음 재검토 조건은 사용자 결정으로 확정한 새 동작이 아니라 이 ADR의 판단이다(이 문서의 판단, 사용자 결정 없음).

- 다중 인스턴스를 도입하여 [ADR-0003](ADR-0003-single-instance-memory-state.md)의 상태 소유·공유 기준이 바뀐다.
- ES256 이외의 서명 알고리즘 요구가 채택된다.
- TCP 클라이언트가 호환성을 유지하면서 ticket을 실을 방법이 생긴다.
- 평문 WS에서 ticket이 노출된 사고가 기록된다.
