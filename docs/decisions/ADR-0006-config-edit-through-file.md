## 2. 배경

관리자는 대시보드에서 설정을 확인하고 재시작 없이 바꿀 수 있는 항목을 편집하려 한다. 기존 설정 파일 편집과 파일 변경 감지 재로드도 계속 사용한다. 두 경로가 다른 설정 원본이나 검증 규칙을 가지면 운영자가 다음 재시작에 적용될 값을 구분하기 어렵다.

이 선택은 [ADR 작성 조건](AGENTS.md) 세 가지를 모두 만족한다.

1. **되돌리기 어렵다.** API 편집 값의 보관 위치는 재시작 뒤 값과 운영자의 파일 편집 절차를 정한다. 별도 파일이나 메모리 전용 적용으로 바꾸면 기존 설정 이관, 우선순위, 충돌 처리와 복구 안내를 함께 바꿔야 한다. 파일 저장과 실행 값 교체의 순서는 성공 응답의 의미와 회귀 시험에도 연결된다.
2. **맥락 없이 보면 의외다.** 웹 API가 프로세스의 실행 값만 바꾸지 않고 운영자가 관리하던 설정 파일을 직접 고친다. 파일 감지가 있는데도 요청 처리 중 직접 교체하는 경로를 더하며, 직렬화로 파일 전체를 다시 쓰지 않는다. 파일 쓰기 권한과 서식 보존이 필요한 이유를 남겨야 한다.
3. **실제 대안을 비교했다.** 보관 위치는 Q167에서 같은 파일·별도 동적 설정 파일·메모리 전용 적용을 비교했다. 적용 경로와 파일 편집 방식은 5절에서 같은 요인으로 비교했다. 주석·서식을 보존하는 의존성 추가는 Q173으로 채택했다.

## 3. 결정 요인

1. 대시보드와 파일 편집이 같은 설정 원본을 사용하고 재시작 뒤에도 같은 값을 유지하는가.
2. 한 요청의 성공 여부를 파일 저장과 실행 값 적용까지 묶어 설명할 수 있는가.
3. 운영자가 쓴 주석·공백·키 순서·다른 값을 보존하는가.
4. 파일 쓰기 권한, 동시 편집 처리와 의존성 유지보수 비용을 감수할 수 있는가.

## 4. 선택 근거

- 같은 파일을 쓰면 실행 중 편집 값과 다음 시작 값에 별도 우선순위를 만들지 않는다. 사용자 결정 2026-11-08(Q167)이 이 보관 방식을 확정했다.
- 파일 감지만 기다리면 쓰기 완료와 실제 적용 사이에 시간이 생긴다. 그사이 다른 변경을 감지하면 API가 쓴 후보의 적용 결과를 같은 응답으로 확정하기 어렵다. 같은 요청에서 재로드 서비스와 직렬화해 교체하면 성공 응답 시점에 그 후보의 적용을 마칠 수 있다. 이 선택은 사용자 결정 2026-11-08(Q177)으로 채택했다.
- TOML을 설정 구조체로 읽고 전체를 다시 쓰면 파일에 있던 주석과 서식을 잃을 수 있다. `toml_edit`는 그 내용을 보존하며 바뀐 값만 고치는 Q167의 조건을 구현하기 위한 선택이다. 사용자 결정 2026-11-08(Q173)으로 의존성 추가를 허용했다. 실제 잠금 파일과 고지는 구현할 때 [라이선스 검사](../how-to/check-dependency-licenses.md)로 확인해야 한다.

## 6. 결과

### 긍정적 결과

- 운영자가 파일과 대시보드 가운데 어느 경로를 쓰든 같은 설정 원본과 재로드 검증을 따른다.
- 재시작 뒤 값이 사라지거나 파일 간 우선순위로 달라지지 않는다.
- 기존 파일의 설명과 배치를 유지한다.

### 부정적 결과와 비용

- 편집을 켜면 서비스 계정에 설정 파일 쓰기·교체 권한이 필요하다. 같은 디렉터리에 임시 파일을 만들 수 있어야 한다.
- 파일 편집 충돌, 쓰기 실패, 서식 보존과 파일 감지의 중복 적용을 시험해야 한다.
- `toml_edit`의 버전·라이선스·고지와 Windows·Ubuntu 파일 교체 동작을 유지보수해야 한다.

### 후속 작업

- 시안·문구·이름·직접 적용 설계는 사용자 결정 2026-11-08(Q174~Q177)으로 채택했다. 구현·테스트는 미실행(구현 전)이다. 후속: 커밋 `7ce077f`에서 구현했고, 커밋 `eae442f`의 두 OS 게이트로 확인했다([작업 6.9 판정표](../how-to/set-up-and-verify.md#42-작업-69-판정표)).
- [작업 목록의 설정 보기·동적 설정 편집 묶음](../TODO.md#6-설정-보기와-동적-설정-편집)에 따라 코드 지도·모듈 설계, 재로드·API·로그·화면·운영 안내를 갱신했다(작업 6.2~6.8).

## 8. 재검토 조건

- 설정 파일이 읽기 전용인 운영 환경에서도 편집해야 한다는 요구가 생긴다.
- 설정 원본을 외부 시스템이나 여러 프로세스가 함께 관리해야 한다.
- 두 OS에서 파일 교체와 동시 편집을 계약대로 보장할 수 없는 제약이 확인된다.
- `toml_edit`로 필요한 서식을 보존할 수 없거나 허용 라이선스 조건이 바뀐다.
